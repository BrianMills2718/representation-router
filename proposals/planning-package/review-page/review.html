Representation Router: planning package: the plan, for your review

complete Complete, pending your review. 2 other open questions (Q3, Q10) do not block it.

The router picks how information is shown to a person: which view answers their question, how the whole page reads, and which checks the built page must pass. It also ships the shared graph viewer other projects draw with. This package records what exists, what was checked, what is still open, and the next plan: make sure a dense graph never freezes a page (issue #169). What you do: Nothing is waiting on you. Every open question is an agent's to settle; read the plan if you want to change what comes next. Each section opens short, with detail behind its expandable parts.

1.Goal: what this plan is for and why

missing The outcome: docs/planning/acceptance-criteria.json is not in this package.

North star

A person looking at any page an agent built for them can answer the question the page exists for from the page alone, because the view was chosen for that question from the owning source rather than laid out by habit (docs/architecture/GOAL.md, North star).

Thesis

Pages stay useful and honest when the choice of representation is made explicitly, before any library is chosen, from the question and the owning source; making the checklist explicit and refusing silent omissions turns "looks finished" into lines a reviewer can falsify (docs/architecture/GOAL.md, Thesis).

What would prove it wrong

Pages built through the router draw the same owner rejections as pages built without it; or consuming projects keep hand-rolling the views the router covers (graph pages written instead of vendoring graph-viewer/); or a page shows a view the owning source could not support (docs/architecture/GOAL.md, Thesis disproof).

Not for

Owning domain semantics, planning state or the write; becoming the planning system; verifying that a claimed "satisfied" check is true (docs/architecture/GOAL.md, Non-goals).
